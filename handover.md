## CURRENT WORK — v1.1.10 See All source-integrity repair

**Reported user defect:** “still seeing in places where 'See All' is showing unrelated and generic shows.” Previous v1.1.7 fix treated `MovieSection.isCurated` specially but did **not** cover every section. Specifically `lib/pages/catalog/catalog_page.dart` ignored the Home row's original `MovieSection.movies` list, re-fetched page zero from a section catalog and continued trying `skip` even when unsupported; `MetadataService.fetchCatalog` defaults missing/invalid base URLs to generic Cinemeta. Known synthetic BestSimilar/Trakt/Simkl IDs could also be queried as fake real catalogs if a section wasn't marked curated. Separately, `BestSimilarScraper.findBest` could pick a different same-year TV/movie if it shared a word or overlapping title; generic suggestions from the wrong source then appeared in home recommendation sliders and their See All.

**Repair in source, v1.1.10+20 (pending new paired CI):**
- `lib/pages/catalog/catalog_page.dart`: seed **exact tapped MovieSection.movies in exact displayed order** as page one. Only the original addon catalog with a real valid HTTP(S) host, real catalog ID, and `supportsSkip=true` can fetch additional pages using exact `addonBaseUrl`, `contentType` and `catalog.id` at the original remote offset. Never fetch from generic Cinemeta for empty/invalid source; curated, synthetic BestSimilar/Trakt/Simkl, or `supportsSkip=false` sections are always source-bound snapshots. Local search applies to snapshot sections; unsupported synthetic genres/pagination are not displayed. Deduplicate page results and stop when skip is ignored/replayed, preserving original items on request failure. Ignore stale in-flight source/filter results.
- `lib/services/metadata/metadata_service.dart`: add **test-only** catalog GET override to validate URL, offset, repeat-page behavior without contacting an actual addon. Production HTTP behavior unchanged.
- `lib/services/metadata/bestsimilar_scraper.dart`: autocomplete source choice requires normalized exact title (handling leading articles), verified movie vs TV type and within one release year where available, not fuzzy shared keywords and year scoring. `lib/services/home/home_page_settings.dart` verifies returned detail-page identity/year for “Because you...” before using its Similar results. Prefer no section to unrelated suggestions.
- Regression tests `test/see_all_source_integrity_test.dart` assert snapshot rows never trigger Cinemeta, known synthetic IDs cannot fetch remote, local curated search stays local, real addon paging uses exact original source and `skip` and stops when source repeats first page, and unrelated BestSimilar autocomplete hits fail. Existing `test/curated_recommendations_see_all_test.dart` retained. Add both to Windows and iOS paired CI. Version 1.1.10+20 in Flutter pubspec, Settings fallback, Windows resource, installer and workflow.
- **Release not yet verified at this checkpoint.** Do not claim v1.1.10 built/published until Windows and iOS tests, analysis, actual signed TrollStore IPA and GitHub/Telegram uploads are confirmed. No real-device verification yet; acceptance needs user to click See All across home sections.
