## HISTORICAL IMPLEMENTATION — v1.1.7 optional title + advanced TMDB filters

**Important TMDB API distinction:** TMDB does not accept text `query` for `discover/movie` or `discover/tv`. It offers separate `search/movie` and `search/tv` text endpoints. `DiscoverFilters` in `lib/services/metadata/tmdb_discover_service.dart` now includes `titleQuery` (default empty), `hasTitleQuery`, `withPage`, and `buildUri` selecting the correct endpoint. `toQuery()` preserves the **existing discover request unchanged** if blank; if nonempty, sends normalized nonempty `query`, `page`, `en-US` response language and adult-off settings and a matching **single-year** TV `year` (covers any episode aired) or Movie `primary_release_year`. **Never send** Discover-only country/language/sort query parameters to Search (TMDB ignores or rejects them).

**Combined filters without faking an intersection:** `TmdbDiscoverService.browse` now branches only for nonempty title and applies local **country**, **original-language**, **year** and **sort** constraints to authentic Search results. TV search rows directly expose `origin_country`; movie search rows may not, so **only when the user deliberately sets text + movie + origin country** the service fetches each **otherwise eligible search-page movie** `/movie/{id}` metadata and verifies original/production-country code. This is at most one extra lookup per candidate, at most the provider page size (20) per user-requested page, all through the **existing 700ms-spaced, cached, in-flight-de-duplicated, 429-cooldown TMDB client**. Filter year/language/min-votes before optional country details, no extra calls without movie country. Sort the filtered page by popularity, rating (>=100 votes for Top rated) or review count. Note sorting is **within each fetched search page**; entire server-wide ranking is not implied. TMDB search raw page count is preserved to allow Load More even when one page has zero qualifying items. UI displays **number of actually displayed filtered titles** rather than falsely claiming TMDB's total raw title count meets the filters. No auto fetch/typing debounce or API calls on every keystroke.

**TV year semantic caveat (documented in UI):** For **single-year** title search, TMDB `search/tv?year=YYYY` matches premiere or episode-airing year and supports returning series; blank-text Discover keeps its full `air_date.gte/lte` range semantics unchanged. For **multi-year TV range with text**, Search API cannot express the Discover airing-date interval in a single text query; client filters against **original first-air/premiere year** and clearly tells users the difference in the UI. Do not claim multi-year text search includes every returning older series. Other types use movie release years. This trade-off avoids performing an excessive number of requests per year and per series without consent.

Shared `_browse` uses titleController content and unchanged filter selections, persists/restores as `adv_discover_query`, and freezes applied filters via `_appliedFilters.withPage` so changing controls before pressing Search cannot contaminate Load More. Primary button reads **Discover Titles** if blank, **Search Titles & Apply Filters** if entered. Search pagination counts and year caveat are honestly displayed; legacy no-text Discover remains intact.

## 4. Database contracts and synchronization details

### 4.1 Why GitHub JSON, not shared SQLite
GitHub repositories expose files, not a managed multi-device writable SQLite service. A SQLite file repeatedly downloaded/overwritten would cause hard-to-merge binary conflicts. Two small, human-inspectable JSON documents with optimistic locking are a practical no-server compromise for watchlists and progress on a few devices.

### 4.2 Watchlist v1
Top-level: **version: 1**, **records: mapping of stable media uniqueKey to record**. Each record includes **item** (MyListItem JSON) and **deleted** boolean; deletion entries survive sync. The merger: fetch newest remote, merge first-device local only if no remote record exists, overlay pending local operations, PUT with remote blob SHA; on 409/422 refetch up to six times. On success, acknowledge only operations matching the snapshotted values, so edits made while uploading are not silently cleared; persist the merged view locally. No shared event history.

### 4.3 Progress v1
Top-level: **version: 1**, **records: mapping from show ID / sessionKey to record**. Each record includes **updatedAt** in UTC, **deleted**, and **item** with the non-streaming ContinueWatchingItem fields (title, type, poster/year, episode, position/duration, last watched, safe source labels). Media URLs, magnet/infoHash, file index and HTTP headers excluded. Merge timestamped recent edits over remote and preserve remote tombstones during first-device import. Remove/complete => tombstone. Session UI generally shows items past 10 seconds and below the completion threshold (**90%**).

### 4.4 Trigger matrix

| Action | My List | Continue Watching |
| --- | --- | --- |
| Local add/remove | Queue and autosync after ~5s debounce | N/A |
| Playback progress | N/A | Local persist during playback, GitHub batch after ~60s |
| Player exit | N/A | Save final timestamp, best-effort immediate cloud flush |
| Open home / Continue Watching | N/A | Cloud refresh at startup / shelf appearance |
| Leave screen open | My List refresh ~every 2 min | Continue Watching shelf refresh ~every 2 min |
| Manual Settings sync | Immediate | Immediate |
| Disconnected/network failure | Keep local list and pending journal | Keep local progress and pending journal |
| Concurrent edits from devices | SHA conflict retry, deletion tombstones | SHA retry, timestamp arbitration, tombstones |

**Caution:** GitHub is not a push notification service; foreground screen refresh and upload throttling determine freshness. Offline saved state and cross-device tests should be checked before making stronger guarantees. Rate limits, token permissions, network failures, clock skew, merged updates and incomplete metadata are expected failure modes.
